# 1.1 报表数据库与交互设计

## 用户路径

Ribbon → Electron 报表数据库 → 创建 → 选来源文件夹 → 选择工作表和表头 → 配置时点/累计、日期、贷款号、金额及组合键 → 扫描更新 → 查看统计/待核对 → 筛选或修改 SQL → 定位源 Excel → 修改保存 → 重新扫描。

左侧列出独立数据库；主区提供归并记录、最新快照、待核对、全部来源、文件清单和扫描历史。筛选生成的语句一直可见，只有主动点击“生成 SQL”才覆盖手工 SQL。结果保留来源按钮；操作不产生数据库编辑接口。

## 结构

| 实体 | 存储及含义 |
|---|---|
| 库 | UUID.sqlite；config 保存名称、路径、表头、字段映射、组合键和精度 |
| files | 规范来源路径主键、SHA-256、修改时间、行数 |
| source_rows | 每个文件的实际贡献行、表名、Excel 行号、键摘要、内容摘要、JSON 原始字段、文本贷款号、ISO 日期、精确整数金额、质量标记 |
| records | 业务键摘要主键，代表源行外键、来源数、冲突标记 |
| scans | 成功扫描时间、文件数、变更/删除数、归并记录数、冲突数 |
| 查询视图 | data / latest / issues / provenance，通过 JSON 提取映射为原始中文列名 |

业务实体与报表贡献分离：一条逻辑记录可对应多个来源；删除某个来源不会误删其他来源仍贡献的记录。快照业务键包括有效日期，不能把不同月份余额覆盖成一条。累计型必须区分业务事件，贷款号不是通用事件主键。没有业务主键时公开标记不确定性，保留同文件的重复次数，避免伪造确定的身份。

精确金额从十进制字符串解析为指定小数位整数，不经过二进制浮点乘法或静默四舍五入。原始金额表示同时保留。读取器单独标记 Excel 数值单元格；这些数值在量化误差不超过 `2 * Number.EPSILON * abs(value)` 时归到已选精度，修复系统导出中的二进制尾差；文本金额和超出误差界限的小数拒绝。SQL 精确合计使用整数列；超过整数范围报错。

## 扫描事务

枚举来源 → BEGIN IMMEDIATE → 比较文件 SHA-256 → 解析变更报表 → 校验结构与金额日期 → 替换该文件全部贡献 → 移除不再存在的文件贡献 → 重建代表记录/冲突 → 再次验证文件哈希和目录成员 → 写扫描记录 → COMMIT。

任一步失败回滚；数据源完全不可用不清空已有库。解析只读取 OOXML 缓存，不运行 Excel 宏、链接或公式。报表读取以只读共享方式打开，前后哈希检测并发保存；极短暂、完全恢复相同字节的变化无法从最终内容区分，但入库内容哈希一致。

查询以只读数据库连接、query_only 和 authorizer 执行，单语句作为子查询包裹，额外语句不能执行。只允许安全读取函数；扩展、ATTACH、写入和 PRAGMA 被拒绝。SQLite 同步计算放入独立 Node 子进程，15 秒超时/取消会结束该进程；这避免线程中原生 SQLite 计算无法及时中断。扫描最多 15 分钟，事务由 SQLite 在中断后恢复。

## 性能和边界

SHA-256 必须读取所有文件，但只解析变化文件。一次最多 10000 个文件，单文件 256 列、200 万格、512 MB 解压内容。分页 IPC 最多 200 行，20,000 行是浏览上限，不是入库或聚合上限。查询页面有内容体积限制，子进程 JS 堆限制 512 MB。

脱敏预览在后台筛选所有替换，最多收集 20001 条以明确标记超限；100/200 条分页渲染。复制只来自已确认的脱敏结果，重新检查源表是否改变，保留文本编号并防止公式样文本在目标 Excel 执行。公式复制为脱敏结果计算值。分词预览计算上限 20000，列表每页 100 行且搜索防抖。

图标采用 32 单位画布、统一 1.65 线宽、实际字形边界居中、4 倍绘制缩小和 DPI 缓存。工作表导航使用虚拟化列表，右键与拖放都重新校验 COM 身份、工作簿归属、只读/保护状态；不支持跨工作簿拖动。
