v1.1 additions (supersede older notes where different)
- Electron now hosts report databases as well as masking/settings. Native navigation remains virtualized WPF.
- Per-library SQLite at %APPDATA%/GridPilot/Databases; registry metadata is stored in each library config.
- ReportReader reads cached OOXML values on a background task, with no Excel automation during scanning.
- Dedicated child processes handle database queries and scan transactions. Killing a canceled/timed-out
  child reliably releases SQLite native work and locks; a worker-thread termination alone does not.
- Source contributions and canonical records are separate. SHA-256 scan, schema validation and a complete
  transaction preserve previous committed data on failure. See DATABASE.txt and docs/v1.1/DESIGN.md.
- Query connections are read-only with SQLite authorizer; unsafe functions/PRAGMA/ATTACH/writes are denied.
- Mask preview is paged (20k cap), clipboard writes text/HTML ClipboardItems after source verification.
- Clean portable packages bundle notices as App/legal.bin, readable from Settings > About.

v0.9 architecture (supersedes the historical decisions below)
- Excel-DNA net462 XLL shim (~0.63/0.70 MiB), external managed assemblies.
- Browser/Electron 44.7.0 win-x64 starts only on masking/settings, exits with its window.
- App local HTML/CSS/JS; sandbox=true, contextIsolation=true, nodeIntegration=false.
- Current-user-only named pipe, random per-window name; no TCP server. Windows GUI
  Electron cannot reliably read inherited stdin, so named pipes are used explicitly.
- A narrow message contract: init, preview, export, cancel, saveSettings, navigationSettings.
- Detached snapshots and masking planning on worker threads. Excel COM only on queued
  Excel macros; async context is restored before returning to Office.
- Save dialog is owned by Chromium so it cannot hide behind Excel. Export verifies
  active source identity/content and refuses existing targets. Cancellation closes no user workbook.
- Source capture uses Find + bounded blocks; SpecialCells is avoided on the source
  because Excel can mark a workbook dirty even on a read. Sparse content uses Find traversal.
- Clean XLSX data written by an owned Excel instance; presentation-only XML parts can
  be transferred from a private SaveCopyAs snapshot. No source worksheet objects or
  relationships are copied. Reopen/recalculate validation precedes final file commit.
- Identity trie replaces the old quadratic residual scan. Identity mentions outside
  selected fields are changed only with the explicit sync-mentions option.
- Lazy navigation/focus event subscription, cached supersampled Ribbon icons, reused
  DIB overlay. Ripple samples update strips and stop at the configured endpoint.
- Navigation restores the visible EXCEL7 child focus without hooks, synthetic keys,
  AttachThreadInput, reparenting or global hotkeys. Excel 2010 MDI path remains to be verified.

Historical architecture notes (v0.8 and earlier):

GridPilot：长期架构与扩展约定
=============================

1. 技术决策

使用 Excel-DNA 1.9.0（固定正式版本）+ .NET Framework 4.6.2 + WPF。
WinForms UserControl / ElementHost 只承担 Office CustomTaskPane 的承载职责。
Ribbon 遵循 Office 2010 原生主题；自定义的现代界面放在 WPF 面板内。
不修改 Excel 窗口父子关系，不使用 SetParent、置顶悬浮窗口或浏览器进程嵌入。

选择理由：XLL 可以按 Excel 位数独立打包；Excel-DNA 的成熟接口覆盖 2010；
.NET Framework 与旧 Office 的部署组合较简单。WPF 提供布局、数据绑定、矢量缩放、
键盘交互和列表虚拟化，适合将多个工具逐步放到统一面板中。
net462 是为减少旧 Win10 的额外安装需求而选择的最低编译基线；装有 4.8/4.8.1 的机器
运行在其已有兼容运行时上。可在保持 Core/API 边界时将来增加现代运行时构建。

没有选择 Electron：它可以作为将来独立工具的前端，但目前会额外引入进程通信、窗口
生命周期、焦点/任务栏处理和大量分发文件，这些并不是工作表导航所必需的能力。
没有选择 Office.js：目标是 Excel 2010 桌面版，不能将现代 Office Web Add-in 能力作为基础。

2. 分层

Ribbon / XLL 启停
  → FeatureRegistry（显式模块注册，统一命令元数据和分派）
    → NavigationModule（面板生命周期、Excel 安全调用队列、定时刷新）
      → ExcelGateway（只在 Excel 主线程访问 COM）
        → WorkbookSnapshot / SheetItem（脱离 COM 的不可变数据）
      → NavigationModel（防抖、搜索取消、结果代次校验）
        → SheetSearch（后台执行，正则超时和总预算）
        → NavigationView（WPF 可复用界面）

src/SheetPilot.Core
  数据模型、查询逻辑、IWorkbookGateway、IFeatureModule、FeatureCommand、FeatureRegistry。
  不依赖 Office、Excel-DNA 或任何界面库；业务测试无需安装 Excel。

src/SheetPilot.UI
  NavigationModel 与 NavigationView；只接收快照、发出操作意图。
  支持脱离 Excel 的真实 WPF 渲染与验证；不持有 COM 对象。

src/SheetPilot.Excel
  组合根 AddIn、原生 Ribbon、ExcelGateway、NavigationModule、WinForms 承载层。
  Office 使用动态 COM 访问 + 框架自带的 COM 类型信息，不需要安装 Office PIA。
  SheetPilot-AddIn.dna 显式打包 Core/UI，不能仅依赖项目引用自动打包。

tests/SheetPilot.Tests
  独立可执行测试程序；搜索、模型更新、真实 WPF 渲染。
  --excel 参数启动独立临时 Excel 实例，验证实际 COM 和 XLL；不会打开用户文件。

3. 线程、错误及生命周期

ExcelGateway 在创建时记录拥有线程，阻止后台 COM 调用。
读取及激活通过 ExcelAsyncUtil.QueueAsMacro 回到 Excel 主线程和可接受宏操作的时机。
编辑单元格时不堆积刷新，最多一个待处理刷新；每个面板最多一个待处理跳转。
搜索只处理快照，不把 Workbook、Worksheet、Range 等传入 Task.Run。
180ms 防抖；取消旧查询；只接受最新代次结果；搜索未完成时不跳转旧结果。
保持 Excel 工作表原顺序；不通过排序和选中事件偷偷切换工作表。
单击或 Enter 才激活；激活前重新检查目标工作簿、页面身份和可见性。

Excel 2010 为 MDI：使用应用窗口句柄对应的单个面板；2013+ 为 SDI：面板按窗口分别创建。
只在用户点击入口时创建面板，避免 AutoOpen 里初始化 CustomTaskPane 的旧版兼容风险。
面板可见时刷新；隐藏后停止周期任务；再次显示重新启动。
识别失效窗口并释放面板；加载项卸载、Ribbon OnBeginShutdown/OnDisconnection 都执行
幂等清理：停止定时器、取消搜索、删除 CTP、释放 ElementHost。
生产宿主不调用 FinalReleaseComObject 破坏共享 Office RCW；显式 IUnknown AddRef 成对释放。
测试程序拥有独立 Excel 实例，可释放自己的 RCW。

页面身份优先采用 CodeName；未保存工作簿 CodeName 为空时使用进程内 COM 身份。
工作簿身份为进程内 COM 身份与名称组合。另存为后旧结果将失效，刷新后恢复。
这些标识仅用于当前会话，不可作为未来跨会话书签数据库的持久主键。

4. 增加功能模块

例如增加“单元格书签”或“批量导出”：
  a. 新建功能模块类，实现 IFeatureModule，提供稳定唯一 Id、Label 和 Commands。
  b. 每个 FeatureCommand 提供 id、名称、描述和处理方法；在 RibbonIcons 中提供自绘图标。
  c. 在 AddIn.AutoOpen 中 Features.Add(new ...Module(...)) 显式注册。
  d. Ribbon 自动从模块生成分组和按钮，不需要修改已有导航回调。
  e. 新 UI 放在 UI 项目或独立 Feature 项目；Excel 操作通过宿主适配器执行。
  f. 模块 Dispose 必须解除其事件、停止计时器、取消后台任务、释放自己拥有的界面。

新增项目必须在 DNA 中显式加入要打包的 Reference，并验证隔离目录下单 XLL 加载。
第一版不从任意文件夹扫描并执行第三方 DLL，避免形成不可控插件加载链。
未来需要第三方模块时，再增加版本化合同、能力声明和可验证的签名/来源机制。

修改文件/工作簿的工具应有独立操作请求模型，列出作用范围和可预览结果，
不要让 ViewModel 直接调用 Range.Value 或 Application.Run 任意脚本。
将错误映射为可理解的界面状态，不能通过全局异常吞噬隐藏失败。

5. 建议演进顺序（未实现项）

阶段 0：目标机兼容验收
  Win10 + Excel 2010 SP2 标准版 x86/x64，特别是任务栏多文件切换、Alt+Tab、关机退出、
  高 DPI、保护视图、实际企业策略。正式大范围使用前完成此关卡。

阶段 1：导航体验
  自定义分组、收藏、最近访问、跨工作簿分组标题。
  当前不具备自定义 PDF 式书签树或单元格地址书签；第一版是 Sheet 页面目录。
  v0.2 已实现 NavigationSettings / SettingsStore：XLL 同目录 GridPilot.navigation.json，
  SchemaVersion=1，数值约束、400ms 合并写入、退出补存、原子替换及 .bak 备份。
  损坏配置回退默认，更改后重建并备份损坏原文；未知版本禁止覆盖；搜索词不保存。
  只读目录给出明确提示并保留会话设置，不静默写入其他目录。进程内多窗口共享配置，
  独立进程间最后保存者胜出，不做实时同步。
  书签持久身份需处理文件移动、另存为、工作表重命名和同名文件冲突。

阶段 2：独立功能模块
  单元格/区域书签、命名区域导航、批量导出、工作簿质量检查。
  输出工具与读取工具分开授权和实现，避免搜索操作变成写入操作。

阶段 3：性能与发布
  大规模工作簿采用事件增量索引 + 低频校验；为长 COM 扫描实现分批主线程执行。
  目前每次全量读取 Sheet 元信息；5000 条纯数据搜索测试不代表 5000 张实际表的 COM 性能。
  锁定依赖并保留构建记录；发布前数字签名；双位数包；升级采用关闭 Excel 后替换文件。
  可提供受控错误诊断导出，不默认上传任何工作簿数据。

6. 已知边界

• 同一 Excel 进程内跨工作簿，不跨 Excel 独立进程。
• 设置通过 XLL 同目录 JSON 跨启动恢复；隐藏页只显示不解锁。
• 本版未承诺新版 Excel 每个窗口的面板状态完全同步。
• Ribbon 的外观由 Excel 决定，不能在 Excel 2010 中整体替换成现代 Office Ribbon。
• 便携 XLL 仍服从 Office 信任策略和用户权限；运行时有临时 HKCU COM 注册。
• 无热更新服务、网络请求、数据上传或遥测。

7. v0.3 可复用偏好控件与布局更新

NumberEditor 统一滑块与数字草稿输入，ColorEditor 统一颜色预览、输入验证和提交。
设置对象只保存已验证值；Enter/失焦提交，Esc 撤销草稿，错误草稿不写入 JSON。
ViewTheme 将五个持久颜色转换为冻结 WPF Brush 与派生状态色；动态资源更新无需替换列表。
ShowTooltips 通过附加属性控制每个提示来源，并在视图路由事件处做统一检查。
新增字段保持 SchemaVersion=1，对 v0.2 配置缺省初始化；不修改旧有字段含义。

原生拖动与应用设置是两条路径：SizeChanged 仅重置250ms观察计时器；稳定后记录宽度，
NativeLayoutGuard 标记来源，避免 PropertyChanged 再调用 Pane.Width/DockPosition。
设置页修改位置/宽度才产生布局请求，75ms合并应用；拖动期间暂停快照刷新。
NavigationModel 按属性精确通知，不因宽度变化重置每条结果的行高/间距/副标题。
WinForms 承载层启用双缓冲并跟随背景色，保留 Office 原生窗口管理。

卸载时显式解绑 CTP 事件、清除本视图键盘焦点并释放承载层。
不可达的 Office RCW 在后台触发回收，避免退出后因空闲不触发GC而延迟释放。
不在 Excel STA 等待终结器，不强制释放生产环境共享 RCW，不退出共享 WPF Dispatcher。

8. v0.4 GridPilot 工具模块

保留 SheetPilot.* 内部程序集/命名空间和已有 COM 标识；产品、XLL、配置和仓库使用
GridPilot。旧导航宏仍可用，新增 GridPilot_ShowNavigation/Rename/Focus/Text/Number/Undo/Settings。
ToolsModule 管理统一设置、模态 WPF 窗口、状态栏提示、聚焦生命周期及 Ribbon 状态。
RenamePlanner 与 NumericConversion 是纯逻辑；UI 只接收快照和操作回调。
WorkbookOperations 在 STA 上重新验证目标身份、内容、名称冲突和保护状态后执行。
重命名采用临时唯一名称两阶段应用，支持 A/B 互换；失败尝试回滚并明确报告恢复失败。
转换先收集区域常量，SpecialCells 结果与原选择交集，逐 Areas 遍历以避免不连续选择扩散。
真实字符串通过 apostrophe Formula 写入，数值通过 Value2 写入，不切换 NumberFormat。
用户选择默认保持视觉位置，所以只将 General 对齐固定为原左右位置；撤销还原原属性。
最近一次成功写操作有会话内逆操作，撤销前验证内容和需还原的对齐属性，拒绝覆盖新编辑。
写入期间临时暂停事件和屏幕更新，finally 恢复；不自动保存工作簿。

FocusOverlay 使用拥有者为当前 Excel 窗口的无激活、鼠标穿透透明覆盖层；不是置顶窗口，
不改变父子窗口关系。活动窗口 Hwnd 向顶层解析，旧接口不可用时回退 Application.Hwnd。
按各 Pane 坐标构造行列区域，RangeFromPoint 校验数据边界，支持冻结窗格的区域裁剪。
普通工作表视图之外隐藏；后台、最小化、编辑等 Excel 不就绪时隐藏。每次启动默认关闭。
覆盖层不更改单元格/条件格式/工作簿 Saved 状态；不随保存和打印输出。
RibbonIcons 通过 GDI+ 直接生成透明 32bit 位图，按宿主 DPI 提供图标，释放缓存随 Ribbon 断开。
Styles.xaml、NumberEditor 和 ColorEditor 由导航及工具窗口共同使用。

9. v0.5 事件、性能与 DPI

ExcelEvents 使用 AppEvents 的 COM connection point，仅订阅选区与窗口/Sheet 激活事件，
不依赖 Office PIA。订阅在 Dispose 成对解除。导航激活事件合并到安全宏队列，读取一次快照
后同步所有可见面板；活动项变化无需重新执行正则或180ms防抖。重复 Sheet key 通过 WorkbookKey
复合身份区分。跳转到新窗口延续导航并复制当次搜索词。
FocusOverlay 的选区事件在 Excel 主线程同步读取几何并更新透明层，不经过 QueueAsMacro。
窗口移动/滚动/缩放由轻量指纹补偿，最多64个可视边界缓存；没有变化时不重建 Region。
空闲时降低补偿频率；前台/Ready/最小化检查仍保留。此实现不宣称跨机器硬实时或零延迟。
内部诊断宏 GridPilot_Diagnostics 输出最近最多256次更新的分位数，不记录单元格内容或坐标。

Navigation PaneWidth 改为逻辑像素，设置/读取原生 Width 时用宿主 DPI 双向换算，避免200%下
MinWidth与CTP物理像素不一致造成裁切。旧版本保存的数字不改名，升级后相同值在高DPI下会
获得完整逻辑宽度；用户可重新拖动调整。
ColorPalette 使用 WPF 渐变直接绘制 HSV 二维色盘和色相条，保留 HEX 输入；弹出层隶属原控件，
卸载时关闭，导航/统一工具设置复用。不引入浏览器组件。


v0.6 原子透明帧与分类设置
------------------------
FocusOverlay 使用 WS_EX_LAYERED / UpdateLayeredWindow 提交单张32位透明位图，不再在
选择事件中更换窗口Region或调整Form.Opacity。相同几何/颜色签名不调用Present，正常点击
中的COM忙碌不触发Hide。诊断分开计数 updates / presents / shows / hides，方便验证是否
存在多余的隐藏重现，而不是只根据静态截图判断闪烁。
独立的16ms原生检查使用前台窗口、菜单模式、禁用状态及子窗口命中路径检测真实EXCEL7。
避免Backstage后方的EXCEL7仍带WS_VISIBLE时误判。该检查不依赖Excel可接受COM调用。
在同进程不同XLMAIN窗口间允许重新获取活动工作簿的owner；不接管其他Excel进程。
顶向下32位DIB与DC在同一窗口/尺寸下复用，只擦除旧色带并填充新色带；尺寸改变或窗口释放
时回收GDI对象，避免每次分配整屏位图。覆盖层继续鼠标穿透、不激活、不修改工作簿。

PreferencesWindow 从 ToolUi 中独立出来，维护分类到内容区域的映射；分类导航与滚动位置
双向同步，所有卡片共用同一ScrollViewer与偏好对象。外观设置变化即时更新资源字典，
关闭时解除订阅；不创建浏览器，不更改既有配置文件格式。
参考：https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-updatelayeredwindow

原样复制（v0.7.0）
------------------
Core/CopyPlanning.cs：范围覆盖与保守公式词法分析，不调用 Evaluate 或 DirectPrecedents。Excel/SelectionCopy.cs：原生排版复制、32768 单元格分块、公式连续段合并写入、递归分组行列布局、条件格式显示快照；所有 Office 调用留在 STA。只创建新结果，失败关闭结果并恢复应用状态；不改变全局计算模式。筛选区域按可见/隐藏连续段复制，防止 Excel 压缩隐藏行。详细行为见 COPYING.txt。
