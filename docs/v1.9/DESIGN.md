# v1.9 Excel AI 工作区

## 批准与恢复

自动批准是本次助手的明确开关，默认关闭，MCP 本身没有启用批准、应用或恢复的工具。主进程仅接受当前主框架的这些 UI 请求。切换会话、恢复或自动应用失败后关闭自动批准。启用时建立新的恢复周期；当前恢复周期绑定工作簿，不能静默改写另一个工作簿。

每次写入均先验证整批目标、再使用 Excel SaveCopyAs 保存完整变更前副本。写入完成后还要成功保存变更后副本，才发布成功结果；写入或副本失败会回滚本批。自动批准连续执行时保留最初的完整副本和每次成功的变更后文件。备份目录默认是当前 Windows 用户 LocalApplicationData/GridPilot/Recovery，工具菜单可打开，不会进入模型上下文附件或便携发布包。

界面快照是最新检查点的变更记录：内容以工作簿对象、工作表和地址为键合并；格式保持范围粒度；对象保存创建参数及实际状态。变更前/后切换仅处理 AI 触及的内容和新建对象，保留其他单元格手工修改。每次切换先验证全部目标，原工作簿关闭、内容/公式类型改变或相关对象被编辑时拒绝覆盖。仍在使用的上下文固定保留；切换与再次写入不会指向同名新工作簿。

内容必须仍与所记录的公式及 HasFormula 类型相符。格式恢复只支持原格式一致的范围；自动批准周期内重叠的格式建议会停止自动批准，要求另行确认，避免扁平化混合样式。已有表格、合并、数组、溢出区域及受保护目标继续排除。若自动回滚本身失败，错误会指向完整备份；不宣称绝对无损恢复。

最新检查点可在助手运行期间反复切换；关闭助手后内存记录释放，完整 Excel 副本继续保留。此版本没有持久化所有历史检查点列表；本地备份不自动清除，用户可按需保管或删除。备份与原工作簿包含相同敏感数据。

## 原生透视表

excel_propose_pivot 使用 Excel PivotCaches.Create 和 CreatePivotTable，不把 Markdown 表格冒充透视表。源范围首行必须非空且唯一，字段必须明确来自源标题。目标必须是新工作表，使用兼容旧版 Excel 的透视缓存版本；支持行、列和多个汇总字段。

恢复前对生成工作表的使用范围、内容、常用单元格格式、边框、尺寸、图形数量、超链接、条件格式数量和透视来源/字段朝向等做指纹校验；检测到冲突则拒绝删除。此检查不涵盖所有 Excel 元数据（例如任意命名区域、打印设置、外部宏的副作用），完整工作簿副本是额外恢复路径。结果超过 100,000 格时回滚创建，不声称支持任意规模透视输出。缓存由 Excel 管理，删除生成表不保证立即移除其内存缓存。

## 窗口与进度

Chromium 继续保持 Excel 所有的顶层窗口，不使用 WS_CHILD/SetParent，以避免 Excel 抢走输入。侧栏去除 window/client/dialog edge，关闭 DWM 非客户区绘制及 Electron 阴影，退出侧栏时恢复样式。隐藏范围精确限定为原生 WindowControls；保留其他 Chatbox 操作。独立窗口仍保留正常窗口按钮。

大表按稀疏范围分块，每块后通过 Excel 宏同步上下文让出执行；统计在后台处理冻结文件。读取固定在开始时的对象上；订阅单元格编辑事件，检测到变化则丢弃快照并请用户重试（依赖 Excel 事件开启）。窗口能继续显示实时格数并取消。未知总量时用不定长细进度条，不伪造上传百分比；网络发送与模型流式回复仍由原生 Chatbox 管理。

公式指引和 schema 明确前导等号、英文函数、逗号、二维形状及旧版函数限制。第一次请求等待原生 MCP 完成工具发现；会话归属使用实际生成会话 ID。未修改认证请求头、模型客户端或原生工具执行循环。闭合原生弹窗遗留的 aria-hidden 仅在没有可见模态窗口时清理。
