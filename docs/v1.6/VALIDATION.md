# v1.6 验证记录

日期：2026-10-16。环境：Windows 11、Excel 16 x64、.NET Framework 4.6.2 目标框架、项目锁定 Electron 运行时。

## 排序引擎与 Excel

独立比较器校验完整 20,000 行 × 20 层结果，升降序交替；验证首行、末行和恢复原序。首次测得读取及计划约 5.0 秒、应用约 2.4 秒；重复测量随主机负载变化，记录于开发机测试日志。

覆盖三层联动、同键稳定排序、中文数字、自定义序列、正则超时、原生混合数据类型、数字文本、布尔值、空白、错误值及等号开头文本。通过配置 JSON 往返测试，确保实际层数和 UI 一致，21 层被拒绝。

验证公式、单元格格式、原生表格（含隐藏标题行）、汇总行、筛选、隐藏表、横向合并、不同高度跨行合并、相交合并块、相邻列数据、外部公式引用和撤销。读取后内容/公式/合并发生变化时，应用旧预览被拒绝。

本地 8 个工作簿样本分别读取后在内存排序、恢复并不保存关闭；覆盖项目表、余额表、行政区划、宏工作簿和旧 XLS。源文件逐一比较 SHA-256，不变。受保护/只读的 XLS 工作表未修改并记录边界；大型行政区划样本对 20,001 行选区测试，不声称处理完整文件。宏以禁用执行方式打开。

另外下载 [Pine & Birch 的公开合成 XLSX](https://www.pine-and-birch.com/sample-files/documents/xlsx)，测试 1,000 行和 25,000 行 Orders 及 Summary，包含公式、日期和筛选。来源文件保持不变，不将本地业务样本打包或上传。

## 界面

使用 computer-use 在真实 Excel 中打开 Electron 排序窗口，插入部门/客户/项目规则、检查升降序及日期显示、应用与恢复。真实导航验证双击进入原地编辑、中文输入、点击其他条目提交；编辑内容未进入单元格。还以公开 25,000 行样表副本实测第 200 页、应用全表排序和恢复原序，并打开本地合并项目表副本检查预览。

生产 Electron 命名管道界面测试覆盖：20 层上限、独立方向、20,000 行最后一页、50/100/200 分页、搜索、规则修改后禁用旧预览、应用/撤销及 780 像素窄窗。页面仅渲染当前页，翻页不重新计算排序。

数据库、普通脱敏、简易脱敏及监管核对生产界面回归通过。完整构建通过 265 项基础、90 项冷启动颜色选择器、52 项功能、27 项升级、169 项 v1、97 项 v1.1 断言。真实 Excel 排序回归 46 项、多级排序 25 项通过，x86 纯逻辑构建及排序检查通过。关闭 Excel 测试中 Quit 返回约 7 毫秒，进程完整退出约 3.1 秒。图标检查覆盖全部 16 个功能及三套配色。

## 边界

排序本体最多 200,000 条数据行与 2,000,000 单元格，预览最多 20,000 行；超出预览上限时显示明确提示。跨行合并采用完整块移动，块内行保持原序，键取首行。

颜色/字体颜色/图标及横向排序通过 Excel 原生对话框完成，不纳入 GridPilot 多级预览。保护、数组公式、动态溢出和透视表由兼容边界检查或 Excel 原生入口处理。没有声称解除保护或覆盖 Excel 自身限制。微软[合并区域排序说明](https://learn.microsoft.com/en-us/troubleshoot/microsoft-365-apps/excel/error-sort-a-range-merged-cell)也明确原生排序存在合并布局约束。

本机未实测 Excel 2010、32 位 Excel 或 Windows 10，因此不将 x64 新版 Excel 测试视为这些环境的验收。
