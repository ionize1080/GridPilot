# 监管变动核对工作区

> 此页保留该版本的设计／验证记录；后续行为以 [当前指南](../README.md) 与 [当前架构](../development/ARCHITECTURE.md) 为准。

## 目标与交付范围

将每期 VLOOKUP、辅助列、数据透视、Top N 小表、SUBSTITUTE / TEXTJOIN 串联成可复用的核对方案。v1.4 在 GridPilot 中新增独立工作区，所有运算在本机完成。源工作簿只读，保留已有宏与公式；结果独立导出。

已实现：来源映射、两期全量归集、专项表组合键关联、指标筛选、多取数项、监管金额匹配、三路核对、分类迁入迁出证据、绝对变动排序、来源行定位、确定性中文草稿、复核补充、方案保存与结果导出。

本版不从自然语言或任意 Excel 公式自动推导监管规则，不自动认定业务原因，不自动提交监管报送。自动识别仅提供映射草稿；会计科目方向、统计范围、币种和分类口径由使用者确认。没有提供完整、权威口径的指标保持待配置。

## 工作区信息架构

| 视图 | 使用者的主要任务 | 信息层级 |
| --- | --- | --- |
| 核对总览 | 选择月度/季度两期日期，运行，发现差异 | 期间 → 一致/异常数量 → 指标对账 → 异常列表 |
| 数据来源 | 选择工作簿、表头、起止行，替换下期文件 | 来源名称 → 文件/工作表/范围 → 有限预览 |
| 指标规则 | 定义监管绑定、取数项、专项关联、筛选 | 基本口径 → 监管数 → 有序取数项 → 关联细节 |
| 明细追溯 | 找到金额变化最大的客户、项目、科目 | 金额桥接 → 可搜索分页明细 → 来源记录 → Excel 行 |
| 报告草稿 | 复核主要变动和待核对项，导出 | 导出方式 → 指标状态 → 自动文字 → 人工补充 |

采用暖白主画布、浅灰侧栏、低饱和陶土色主按钮、细边框、节制的状态色。运行完成后期间配置折叠，结果优先；大表分页为每页 50 行，横向滚动限制在表格内部。原始记录在模态窗口查看，支持键盘操作与焦点轮廓。

## 数据契约

方案 `schema=1`：名称、两期日期、核对容差（元）、展示单位、来源、规则。保存方案不带原始业务明细；本地绝对路径属于方案内容，分享前按需要替换。

来源：稳定 ID、文件路径、工作表、表头行、数据起止行、已确认表头。支持 `.xlsx` / `.xlsm`，通过 Open XML 读取已保存缓存，既不执行宏也不刷新连接。无缓存公式以明确错误对象传递。错误只在实际使用其字段时影响指标；闲置的辅助列错误不阻断原始字段取数。

取数项：来源、角色、组合业务键、归集维度、金额字段、原表单位、加减方向、日期字段、筛选条件、专项关联。角色为上期、当期、发放、回收、其他调整。财务指标可用多个科目取数项和正负号构造净额，例如借方余额减贷方余额；同一科目多金额项是明确加总，并不擅自去重。

组合键始终为文本元组，不以拼接分隔符代替结构化键。前导零和长编号保留。余额应使用贷款号/科目号、币种、机构等足够唯一的组合；流水应优先使用交易唯一编号。自动建议的贷款号、发放号、日期、回收类型并不保证唯一，重复项必须补键或核实。

归集维度两期应语义一致、顺序相同。名称发生变化时建议使用稳定客户号/项目号分组，否则旧名和新名会显示为两个组。客户 → 项目可通过组合维度实现；本版不提供任意层级树的展开。

专项关联为多个精确键的一对一/多对一查询。可串联多个专项表，每次带入一个字段作为筛选条件；两个以上字段可重复添加关联。缺失键、未匹配、目标键重复均进入异常，禁止静默选首行或多对多金额放大。两期分类表应分别绑定两期取数项。

## 金额和期间

金额解析支持十进制、规范千位分隔和科学计数。先转换成元，再按百万分之一元四舍五入，用 BigInt 汇总。展示金额独立四舍五入为两位，核对使用内部精度。空金额、错误金额与数值零不同。原表单位支持元、万元、亿元，不混加原币；应选择折人民币字段或先完成可靠的汇率转换。

时点日期列如有配置，必须等于对应比较日；流水日期取 `(上期日期, 当期日期]`。日期列未选时由使用者保证文件覆盖范围完整。月度/季度是日期区间，不对累计金额自动差分；季度流水必须提供全季度记录，累计财务报表需要配置当期减上期的取数项。月份字段 YYYYMM 不等于月末日期，不应直接选作精确时点日期列。

## 计算与核对

1. 两期分别按本期适用的筛选条件取数；以相同顺序的维度元组归集，取两期及流水维度的并集，保留新增、退出以及仅有流水的组。
2. 底层变动 = 当期金额 − 上期金额。
3. 监管差额 = 监管当期 − 监管上期；有差值列时，还校验其内部一致性。
4. 分别检查上期底层与监管金额、当期底层与监管金额、两者差额，避免“两边同错但差额正确”。
5. 余额类型且发放/回收齐全时：现金变动 = 发放 − 回收 + 已登记调整；未解释差额 = 底层变动 − 现金变动。
6. 对两期均存在的业务键，识别是否从筛选范围外进入或从范围内退出；按上期余额报告迁入/迁出存量。该金额是余额变动中的结构性证据，不与现金流自动相加。汇率、核销、转让、科目重分类等需可靠专项数据后作为带符号调整项登记，避免自动重复归因。
7. 变动按绝对值降序，取前 1–20 项，余项合计明确写成“其他净变动”。合计与明细始终可以相互核对。

目前的筛选是多个条件同时满足，单字段“属于”用 `|` 表示多个值。支持等于、不等于、包含、前缀、为空、大于、小于。复杂嵌套逻辑、比例权重、Excel 公式解析及跨指标公式依赖不在本版范围；应在源表准备可核实字段，或者拆分为互不重叠的取数项。余额取数项重复业务键会报异常，不将相互重叠的范围简单相加。

## 状态与恢复

| 状态 | 含义 | 输出行为 |
| --- | --- | --- |
| 核对一致 | 两期金额和差额在容差内，已配置的流水核对也一致，无跳过异常 | 可生成待复核草稿 |
| 存在差异 | 金额或桥接差额超容差 | 保留金额和差额，明确待查 |
| 部分结果 | 缺键、错误金额、重复键、关联异常等记录被跳过 | 可继续其他指标，草稿标记不完整 |
| 待绑定监管数 | 底层计算可用，尚无监管匹配 | 不声称监管一致 |
| 已跳过错误 | 指标配置、字段或来源不可用 | 仅跳过此指标，其余继续 |
| 手动跳过 | 使用者选择本期暂不处理 | 保留原因与状态 |

异常行不被修改或回写；部分结果中的金额是成功处理行的汇总，不能当成完整报送数。重复键保留首条供诊断，其余列入异常，整指标强制不完整。异常总览前 100 条显示，完整 JSON 导出包含全部。

执行前重新读取全部被引用的来源；读取前后校验文件 SHA-256，检测读取期间变化。单来源失败转为来源错误，只有依赖该来源的指标受影响。计算在独立 Worker 中执行，可取消；读取中的单个 Excel 文件需等本次读取返回后停止后续工作。新运行失败或取消不会重新展示旧结果。修改规则/期间/来源使旧结果失效；不会因切换标签丢失已生成结果。

## 报告与审计

报告为确定性事实模板，不调用大模型或上传业务资料。内容包含期间、两期数、净变动、主要客户/项目、其他净变动、流水和未解释差额、分类迁移、核对状态。支持每指标保存自定义文字模板，用 {指标}、{当期}、{主要变动} 等占位符替换事实字段；未知占位符报错，不完整状态提示始终追加。人工“复核补充”独立于自动事实，导出保留。

- Markdown：可读报告草稿、规则指纹、核对状态、异常和复核补充。
- CSV：用“行类型”区分维度汇总与来源明细。汇总金额每组只出现一次；明细行包含逐笔金额、角色、文件、表、行，按角色加总。文本字段做公式注入防护。
- JSON：方案快照、SHA-256 来源清单、指标结果、逐笔追溯、异常、复核补充；金额字段是百万分之一元的整数字符串。

源文件后来被修改，旧结果仍代表当时哈希对应的数据；定位 Excel 只提供位置，正式复核应重新运行。导出结果不含源工作簿本身，不保证源文件长期可用。重启后通过方案重新运行；本版不实现自动保存运行历史或多用户审批流。

## 架构和验证

Excel Ribbon → 受当前用户 ACL 保护的命名管道 → Electron 主进程 → 只读 ReportReader → 核对 Worker → 沙盒渲染界面。窗口继续沿用禁止远程导航、禁止任意脚本执行和禁用 Node 集成的策略。来源须经过文件选择或方案打开授权；来源定位须属于当前运行清单。

20 个独立引擎场景覆盖金额精度、全量并集、差额一致但余额错误、日期边界、分类迁移、财务正负项、重复/空键、公式错误和单指标失败隔离。Electron 集成验收覆盖真实 IPC、Worker、方案加载、来源定位、导出、失效、跳过和窄屏。脱敏底稿使用同一个生产读取器和引擎，另行独立汇总对账；原文件 SHA-256 前后不变。完整验收结果见仓库 VALIDATION.txt。

后续可扩展：可视化嵌套条件、版本化指标库、专项权重/汇率规则、财务勾稽表达式、运行历史与差异比较、XLSX/Word 模板输出、经过授权的模型润色。以上未实现功能不作为本版验收承诺。
